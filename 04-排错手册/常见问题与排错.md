# Duix.Avatar 常见问题与排错手册

> 安装/使用过程中遇到问题，先在这里找。
> 找不到再去 [官方仓库](https://github.com/duixcom/Duix.Avatar) 和
> [官方 Issues](https://github.com/duixcom/Duix.Avatar/issues) 查。

## 一、安装阶段

### 1. 拉镜像报错 `net/http: request canceled` / 连接超时

**现象**：
```
Error response from daemon: Get "https://registry-1.docker.io/v2/": net/http: request canceled while waiting for connection
```

**原因**：Docker Hub 官方源在国内访问不稳定。

**解决（选一）**：
- 开启代理的**全局模式**，然后重试
- 配置国内镜像源：Docker Desktop → Settings → Docker Engine，在 JSON 里加：
  ```json
  {
    "registry-mirrors": [
      "https://docker.zhai.cm",
      "https://a.ussh.net",
      "https://hub.littlediary.cn",
      "https://hub.rat.dev",
      "https://atomhub.openatom.cn",
      "https://docker.m.daocloud.io",
      "https://docker.1ms.run"
    ]
  }
  ```
  点 Apply & Restart，然后重跑安装。
- 注：镜像源会变化，失效就搜「docker 镜像源 最新」。

---

### 2. 提示没有 D 盘

Duix.Avatar **强制要求 D 盘**（客户端内部写死了 `d:/duix_avatar_data`）。

**方案一：subst 映射（最快）**
```cmd
subst D: F:\DuixData
```
- 前提：F 盘有 30GB+ 空间
- **必须配置开机自启**，否则重启失效：
  在 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` 下建 `map_drive_D.bat`：
  ```bat
  @echo off
  if not exist "D:\duix_avatar_data" subst D: "F:\DuixData" >nul 2>&1
  exit /b 0
  ```

**方案二：新建分区**
用「磁盘管理」从其他盘压缩出 30GB+ 新建 D 分区。

---

### 3. 容器起不来 / 一直 Restarting

**先看日志**：
```cmd
docker logs duix-avatar-gen-video --tail 50
docker logs duix-avatar-asr --tail 50
docker logs duix-avatar-tts --tail 50
```

**常见原因**：
| 现象 | 原因 | 解决 |
|---|---|---|
| 日志报 CUDA / driver 错误 | 显卡驱动过旧 | 更新 NVIDIA 驱动到最新 |
| 报 `nvidia-container-cli` 错误 | Docker 未识别 GPU | 确认 Docker Desktop 用 WSL2 后端，且 `docker info` 里能看到 nvidia |
| gen-video 报显存不足 | 显存 < 12GB | 用 lite 方案 |
| 50 系显卡报架构不支持 | 镜像不含 Blackwell 支持 | 用 `docker-compose-5090.yml` |

## 二、使用阶段

### 4. 新建模特报错（图片报错）

**原因**：用于创建模特的视频**必须有声音，且是人在说话** —— 程序要用这段声音做克隆。

**解决**：换一段 10 秒左右、有人声的视频。

---

### 5. 定制模特报错 `Connection refused`

**日志特征**：
```
建立funasr连接异常：[Errno 111] Connection refused
AttributeError: 'NoneType' object has no attribute 'send'
```

**原因**：**Duix.Avatar-asr 服务启动较慢**，还没就绪就发起了克隆。

**解决**：
- 等服务端启动后**等几分钟**再操作
- 如果机器内存只有 16GB，ASR 可能根本起不来 → 建议升级到 32GB
- 确认 `duix-avatar-asr` 容器是 `Up` 状态

---

### 6. 生成视频卡在某个百分比

**检查**：
1. 三个容器是否都 `Up`？特别是 `duix-avatar-gen-video`
2. GPU 是否在工作？运行 `nvidia-smi`，看显存占用和 GPU 利用率
3. 看 gen-video 日志：`docker logs duix-avatar-gen-video --tail 100`

**常见**：显存被其他程序占用（浏览器、游戏、其他 AI 工具）。**关掉占显存的程序再试**。

> 提示：RTX 3060 12GB 跑任务时会吃满显存，生成期间尽量别开别的吃显存的软件。

---

### 7. 客户端打不开 / 双击没反应

**检查快捷方式指向**（很可能指向了不存在的路径）：
- 右键快捷方式 → 属性 → 看「目标」路径
- 确认那个 exe 文件真的存在

**如果路径失效**：重新到 [Releases](https://github.com/duixcom/Duix.Avatar/releases) 下载安装包重装。

---

### 8. `heygen-tts 一直重启`

见官方 issue：https://github.com/duixcom/Duix.Avatar/issues/69

## 三、性能优化

### 9. 显存不够怎么办

**方案 A：lite 模式**（仅视频生成）
```cmd
docker compose -f docker-compose-lite.yml up -d
```
- 缺点：没有语音克隆/识别能力

**方案 B：按需启停服务**
生成时只需要 gen-video + tts，ASR 只在「新建模特」时需要：
```cmd
docker stop duix-avatar-asr          &  rem 建模完成后可以停掉，省显存
docker start duix-avatar-asr         &  rem 需要建模时再启动
```

**方案 C：在 Docker Desktop 里调 WSL 内存上限**
（对内存不足的场景有帮助）

## 四、日常运维

### 10. 常用命令速查

```cmd
:: 查看三个服务状态
docker ps

:: 启动全部服务
docker start duix-avatar-gen-video duix-avatar-asr duix-avatar-tts

:: 停止全部服务（释放显存）
docker stop duix-avatar-gen-video duix-avatar-asr duix-avatar-tts

:: 查看某个服务日志
docker logs duix-avatar-gen-video --tail 100 -f

:: 看 GPU 占用
nvidia-smi

:: 看镜像占用空间
docker system df
```

### 11. 镜像/数据占用说明

| 项目 | 位置 | 大小 |
|---|---|---|
| Docker 镜像 | Docker 数据目录（默认 C 盘） | 约 110GB |
| 数字人数据 | `D:\duix_avatar_data` | 30GB+ |
| 生成的作品 | `D:\duix_avatar_data\face2face\result` | 随使用增长 |

C 盘不够可在 Docker Desktop → Settings → Resources → **Disk image location** 改到其他盘。

## 五、自查清单（提问前必做）

1. **三个服务是否都是 Up？** → `docker ps`
2. **机器是否真有 N 卡且驱动正常？** → `nvidia-smi`
3. **客户端和服务端是否都是最新版？** → 重新 `docker compose up -d` / 重新下载客户端
4. **看 [GitHub Issues](https://github.com/duixcom/Duix.Avatar/issues)** —— 你遇到的问题很可能已有人解决
