# 参考音增强与定版参数 · 调优方法论

> 本文记录「F5 生成语音发闷 / 含糊」的排查过程与定版结论，供 AI 与进阶用户参考。
> 结论一句话：**「提亮参考音」比「加推理步数」有效得多。**

---

## 一、问题现象

用户反馈生成语音「含糊、像嘴里含着东西、类似口吃」，但文本已清洗干净、ASR 也能正确转写。
→ 判定为**音色 / 咬字清晰度**问题，非文本问题。

---

## 二、诊断方法（可复用）

用 `librosa` 计算**频谱特征**，客观量化「闷不闷」：

| 指标 | 含义 | 越大越 |
|---|---|---|
| `spectral_centroid` 谱质心 | 能量重心频率 | **亮 / 清晰** |
| 高频占比（>4kHz） | 高频能量比例 | **清脆** |
| 齿音带占比（5–10kHz） | 嘶声/齿音量 | 过大会**刺耳** |
| 削波样本数 | 峰值 >0.99 的样本 | 过大会**毛刺** |

先对比「源音 vs 生成音」的质心，判断是**源音本就闷**还是**模型把它变闷**。

**本次实测**：源头音频（视频音轨）质心仅 **1510Hz**（偏闷），生成音质心与参考音接近
→ 说明**闷来自源音本身**，F5 没有额外变闷。

---

## 三、参数 A/B 实测（同一句文案，seed=42）

| 变体 | 处理 | 谱质心 | 高频>4k | 齿音5–10k | 削波 |
|---|---|---|---|---|---|
| A 基线 | nfe32 / cfg2.0 | 1697Hz | 9.7% | 5.6% | **126** ⚠️ |
| B | nfe64 | 1698Hz | 9.7% | — | — |
| C | nfe64 + cfg2.8 + sp0.95 | 1764Hz | 11.6% | — | — |
| D | **增强参考音** + nfe64 | 1916Hz | 12.6% | 6.8% | 25 ⚠️ |
| **F** | **v1模型 + 增强参考音** | **1907Hz** | — | **6.8%** | **0** ✅ |
| H | 增强参考音(强0.95) + nfe64 | 2083Hz | 15.2% | **8.1%** | 32 ⚠️ |
| I | v1模型 + 强增强 | 2012Hz | — | 7.9% | 0 |

### 结论

1. **加推理步数（32→64）几乎无效**：质心 1697→1698Hz。
2. **增强参考音最有效**：质心 +200~340Hz，高频占比 9.7%→12.6%+。
3. **不是越亮越好**：H 最亮（2083Hz）但齿音 8.1% 且**有削波**，会引入毛刺。
4. **v1 模型 + 中度增强（F）最稳**：够亮、齿音适中、**零削波**。

## 四、定版参数

| 项 | 值 |
|---|---|
| 模型 | `F5TTS_v1_Base` |
| 参考音 | 经 `boost_ref.py` 增强（去静音 → 3kHz 高通×0.55 → RMS→0.1） |
| nfe_step | 64 |
| cfg_strength | 2.5 |
| speed | 0.95 |
| seed | 42 |
| 输出 | 24kHz 生成 → 重采样 16kHz 单声道 PCM_16 |

## 五、参考音增强脚本原理（`boost_ref.py`）

```python
# 1) 去首尾静音
yt, _ = librosa.effects.trim(y, top_db=30)
# 2) 提取 3kHz 以上成分并叠加（presence boost）
b, a = scipy.signal.butter(2, 3000/(sr/2), btype="high")
yb = yt + 0.55 * scipy.signal.filtfilt(b, a, yt)
# 3) 响度归一化到 RMS=0.1
yb = yb * (0.1 / rms(yb))
```

- 增益 `0.55` 是「够亮且不刺耳」的平衡点；`0.95` 更亮但齿音偏重。
- 归一化到 RMS 0.1 与 F5 内部 `target_rms` 一致，避免响度不匹配。

## 六、还有哪些没用上的招（备选）

如果增强参考音后仍觉得闷，可再试：

1. **参考音去噪 + 去低频隆隆声**：对参考音做高通 80Hz + 降噪，去除房间混响/底噪。
2. **换参考片段**：从更清晰、更近距离的录音里另取 5–8 秒。
3. **换引擎**：GPT-SoVITS v2final（音质另有一番特点，但句间停顿是它的短板）。

> ⚠️ 长参考音（10s+）风险：参考文本若没逐字对齐，模型会把参考文本**漏进正文**。实测翻过车，故不推荐。

---

## 七、一句话总结

> 觉得闷，先**提亮参考音**（响度归一化 + 高频提升），别去加推理步数。
> 选型别只挑最亮的，要同时看**齿音占比**和**削波**——「最稳」胜过「最亮」。
